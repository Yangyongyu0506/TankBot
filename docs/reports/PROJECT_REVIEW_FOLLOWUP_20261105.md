## Serena调用关系核查与局部提取理由

使用Serena的`get_symbols_overview`、`find_symbol`和`find_referencing_symbols`梳理Python符号，并定向读取实现；JavaScript/Rust/YAML/CI以源码检索和实际运行补充。没有将原报告的索引数量冒充本轮全仓覆盖率。

| 原职责集中点 | 当前调用/责任边界 | 保留原因 |
| --- | --- | --- |
| Authority构造中的课程配置块 | Authority.__init__ → configure_course_runtime；只装配公开初始模型/模块参数 | 物理、输入冻结、授权、提交与评分继续归Authority，未引入另一套课程调度 |
| Supervisor.submit/_read/finish | RuntimeTiming只观察发送、接收和固定门；Authority._commit仍执行协议/权限/时间验证 | Worker给出的模块耗时不可信，不能影响授权或扩大预算 |
| ModuleRunner.step/ModuleContext.publish | 共用MESSAGE_TYPES及decode_message；update诊断通过显式Context授权并由Authority复验 | Schema仍是独立协议契约；发布类型注册不等于给玩家新增能力 |
| WorkspaceAPI与WorkspaceStore.read/_write | Maintenance复用原transaction、CAS、不可变对象及最终原子HEAD | 不在新模块重建一套并发/版本语义；清理与恢复均显式 |
| 原生server/browser_server资源与管理分发 | management共享资源清单及实验命令，Transport身份/Origin/CSP检查各自保留 | 本机宿主与浏览器文件启动器的信任边界不同 |
| navigation_templates大字符串 | 两个航点脚手架读取只读templates/navigation资源 | 提取前后生成字节摘要一致，不触发玩家源码替换或来源识别变化 |

新实验的数据流为“已冻结授权输入→有界记录→独立候选Worker→Authority校验→获授权的误差/输出视图”。私有参考只存在Authority会话；Worker、导出和重新导入的输入都没有真实目标状态。实验输出不能提交给当前物理世界。

## 运行证据的含义

原生和Firefox/Pyodide均已执行实际F2保存/短测/部署、录制、双版本比较、Python异常、容量预览/清理/恢复流程。完整课程通关未在本轮重新逐关人工验证；既有十关的权限、时序、冻结行为、升级、部署和进度由回归守护。前置c0/c1通关记录是隔离夹具，没有操作日常userdata。

浏览器验证中确实出现过轻量滤波版本的20ms截止，结构化记录表明收到时已迟到。模块内部耗时和桥接耗时低于Authority总往返，仍不能仅由差值断定某一队列或OS调度是唯一原因。保留失败，报告实际位置/样本与统计；不以重试成功删除失败证据，不扩大预算，也不宣称已完成性能优化。

## 尚需继续的工程工作

1. **扩大耗时样本而不改变语义。** 固定输入、配置和启动点，覆盖冷/热启动、UI开关、不同负载；分别观察原生/Pyodide截止和主体执行分位数。先定位桥接外延迟，再评估局部优化。
2. **控制器对照独立建设。** 从同一已解析场景创建两个新实例，固定初态、seed和首次控制时刻，再记录输出改变后的观测。当前滤波回放拒绝执行器，没有新的控制器对照UI。
3. **逐个扩展实验组件。** 先决定是否接入Navigation C2，再考虑C4/C5多模块预测/控制分段诊断；每次都要明确权限和评价时间对齐，不能直接复制目标滤波器合同。
4. **逐项提取职责。** Authority任务适配/输出处理及其余教学字符串继续以冻结基线、迁移和两环境打包检查为门，不按行数推进大重写。Schema与SDK注册之间仍需一致性审查，并未生成全部类型。
5. **平台与隔离另行验证。** Windows/macOS构建配置不等于玩家流程已测；其他浏览器、独立静态网页持久化和Arena OS沙箱仍未解决。
