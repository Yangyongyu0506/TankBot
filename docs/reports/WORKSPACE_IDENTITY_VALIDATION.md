# 默认 Campaign 工作区身份与源码恢复验收

日期：2026-10-27。设计与实现边界见 [ADR-0040](../adr/0040-stable-campaign-workspace.md)、[17](../17_EDITOR_AND_DEPLOYMENT.md)。本轮处理 C1/C2 F2 中已写算法变成模板的问题，不改变上一轮 C3/C4 类型化极坐标接口。

## 根因与实际恢复

原工作区 key 包含 control_sources。C0 的人工底盘、Weapons 的禁用底盘、程序武器对应不同库；同一服务内切关虽然一直保留源码，重启后从另一个关卡启动却会打开另一个初始项目。原测试没有覆盖该直接启动路径。

现场旧项目中，C1 的 SE(3) 和 C2 的 KF 实现仍在 C0 起始项目内；其他两个控制 profile 只有生成模板。已将原项目完整复制到稳定 Campaign 库，确认 HEAD、C1/C2 文件及全部 **36 个历史版本、84 份归档及 HEAD 文件**的内容摘要与源库一致。全部旧目录、revision、ledger、archive 与独立通关进度保持；未用测试参考答案替换玩家源码。C0–C5 六种直接启动配置现均重开同一目录。

新 key 仅包含 seed/campaign scope；沙盒与显式 --workspace-store 保持原语义。自动恢复不按时间戳选择：仅有一份非模板实现时选择它，多份已编辑候选明确拒绝自动选择/合并，保留所有内容。目标已存在、并发、复制失败、历史损坏、缺 HEAD 和不安全链接均有边界测试。

## 测试结果

- 存储领域 **13 项通过**，包含逐关重启、真实旧分库结构、较新模板不覆盖旧实现、所有历史/归档逐字节比较、冲突拒绝、并发和原子发布重试。
- 全量 Python 回归 **187 项通过，111.211 s**；日志 `.m1-cache/workspace-identity/python-tests.log`。
- 浏览器可信与玩家源码 bundle 已重新准备；本轮无 UI 布局、Game Core、协议或物理改动。

## 限制

旧服务实例不会在磁盘源码变化后热切换目录，需重启游戏服务才能选择恢复后的默认项目。运行旧实例继续编辑旧库会产生独立分支，不自动合并。多份已编辑旧项目需要明确选库；未来项目选择 UI、云同步与多个存档槽位未在本轮实现。
