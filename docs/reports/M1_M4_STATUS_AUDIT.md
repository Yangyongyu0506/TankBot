## 本轮核对的三个容易混淆之处

1. **源码完整保留**：所有已保存文件跨关卡逐字节保留，不限 TODO。运行状态在重新部署/重试后重置；框架升级是明确确认的另一个事务。新增测试同时修改框架、JSON、算法和自建文件后切换 C0/C1/C2，再逐字节核对。
2. **依赖为课程规则**：自动安装游戏环境不代表玩家能安装任意算法库。当前外部库仅开放 NumPy，配基础标准库/SDK/自建模块；这不是一个待补的自由 pip 安装入口。策略与 NumPy 矩阵接口见 [23](../23_PLAYER_CODE_AND_LIBRARIES.md)。
3. **C2 不是历史 tuple**：measurements 是当次 0/1 个目标对象；数值坐标可转为 `(N,2)` 数组，协方差已改为二维 ndarray。单个变量替换不会自动增长；玩家自己无限保存历史仍会增长。缓冲上限和日志见 [24](../24_RUNTIME_LOGS.md)。

## 后续阶段与建议顺序

完整多模块图、C3/C4 的自主定位/建图属于 M5；规划控制、自主决策、Algorithm Lab、竞技服务器/强沙箱分别仍属 M6–M8，不将它们倒算成 M1–M4 已完成的功能。

建议先补其他平台执行记录及长时资源/存储回收专项，再按路线图推进 M5a。若优先推进 M5，也须保留这些开放项，不能以增加关卡替代平台与资源验证。

历史报告中的早期模板、测试数和“会话进度”仅描述当时构建；当前存档以 [22](../22_SETTINGS_MODES_AND_PROGRESS.md) 为准，日志/依赖与新验收见 [玩家 Runtime 报告](PLAYER_RUNTIME_VALIDATION.md)。本核对不声称重新执行了所有历史平台/性能测量。
