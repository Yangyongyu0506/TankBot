# 11 关键架构问题与回答

## 目的与使用方式

本文件逐项回答需求 Q1–Q15，提供推荐方案、理由、风险和验证方向。详细接口以引用领域文档为准，不在此创造第二套命名。所有推荐均受 Accepted ADR 约束；具体技术待验证项保留 Proposed。

## Q1 未定位但需要键盘移动，如何设计局部视图？

推荐固定车体图标与 `base_link` 传感器面板，只显示雷达/局部 scan 实际测量和许可接触提示；键盘通过 cmd_vel 发布车体 Twist，分量受底盘能力限制。全局图在没有估计时不显示坦克，Camera 不读真值。这样无需定位也可探索，同时保留真实的遮挡、噪声与延迟。风险是方向感不足，需提示前/左方向并提供练习；验收由关闭所有位姿源后的可玩性测试完成。见 [04](04_STATE_AND_VIEW_MODEL.md)、ADR-0007/0014。

## Q2 严重错误的估计位姿如何显示？

数值/时间/帧合法就按估计显示，标记来源和不确定度；跳变清空插值历史，越界显示估计越界提示。不得吸附真值或据此修改碰撞。这样能让玩家识别定位错误。风险是视觉与碰撞不同带来困惑，使用局部接触反馈和停止后评估解释；验证错误估计 2 m 时真实轨迹不变。见 [04](04_STATE_AND_VIEW_MODEL.md)、ADR-0006。

## Q3 禁用 System Pose Provider 后怎样堵住旁路？

服务器 Gateway 按白名单生成 DTO；音效、弹道、相机、特效、调试、地图资源和 Replay 都执行相同信息策略。System Provider 不注册公共频道。理由是只隐藏主坦克图层会留下大量位置侧漏。风险包括缓存、消息大小和时序侧信道；做抓包、双世界输出对照与所有表现通道审查，不宣称绝对零侧信道。见 [04](04_STATE_AND_VIEW_MODEL.md)、[08](08_RUNTIME_AND_SECURITY.md)，ADR-0006/0007。

## Q4 多个定位算法同时发布时如何选择？

各模块发布独立候选，Selector 是标准 `/robot/localization/pose` 唯一写者；来源由玩家或任务固定优先级显式选择。禁止真值选优，失效不回落系统真值。这样可公平比较并避免消息到达竞态。风险是选源切换跳变；tick 边界切换并重置插值，测试同 tick 多源与旧租约消息。见 [04](04_STATE_AND_VIEW_MODEL.md)，ADR-0007。

## Q5 怎样逐步接管系统功能而不改 Engine？

系统/玩家模块使用相同类型端口，LevelDefinition 调整连接、Provider、能力和控制租约。Core 只接收已验证执行器命令，不知道用的是系统还是玩家算法。代价是必须提前定义可替换端口；风险是关卡内容偷偷引入特殊引擎分支，代码审查禁止这类捷径。见 [05](05_ROBOT_MODULE_SYSTEM.md)、[09](09_LEVEL_DESIGN.md)，ADR-0001/0008。

## Q6 模块直接调用还是 Topic，能否混合？

模块内算法/工具直接调用，模块间用声明 Topic 连接。这样保留单元测试与低学习成本，也支持录制、权限和系统替换。代价是跨模块至少一个提交量子的延迟；风险是持有其他模块对象绕过调度。测试输入快照隔离，反馈环只能跨 tick。见 [05](05_ROBOT_MODULE_SYSTEM.md)、[07](07_SIMULATION_DESIGN.md)，ADR-0008/0010。

## Q7 如何兼顾填空与完整编程自由？

函数包装、Module 类、多模块和 RobotApp 都编译/绑定到同一 Contract；模板生成 package、import 与启动入口，玩家只填算法。高级 Publisher/Subscriber 仍遵守声明端口和配额。风险是包装器与高级 API 语义分叉；用同一夹具比较等价函数与类，并保留玩家函数库。见 [05](05_ROBOT_MODULE_SYSTEM.md)、[06](06_WORKSPACE_AND_TEMPLATES.md)，ADR-0008/0009。

## Q8 Web 本地与远程怎样共享协议和逻辑？

共享纯 Core、Schema、序列/时间/权限语义；WASM Worker 用 MessagePort，远程 Host 用 WebSocket，原生用 IPC。Authority 位置与安全等级不同，不强求相同进程结构。风险是某 Adapter 绕过校验或引入 OS 依赖；同套正反夹具跑所有 Adapter，平台支持按实际报告声明。见 [02](02_SYSTEM_ARCHITECTURE.md)、[03](03_PROTOCOL_SPECIFICATION.md)，ADR-0002/0005。

## Q9 Python 过慢或崩溃时怎样保持仿真稳定？

Core 从不直接调用玩家函数；Supervisor 管理有界批次、外部运行预算和固定生效 tick，迟到丢弃。底盘另按配置的 cmd_vel_timeout 将过期速度目标归零，租约撤回无需等超时；两种保护不是速度消息的执行起止字段。风险是单 worker 卡死影响本机器人全部模块，初期接受该故障域但不影响其他机器人；通过无限循环、内存越界和强杀测试验证。见 [07](07_SIMULATION_DESIGN.md)、[08](08_RUNTIME_AND_SECURITY.md)，ADR-0010/0013/0014。

## Q10 怎样确保文档 API 与实现一致？

Schema 与 JSON 夹具是结构基线；实现时生成/核查 TS 与 Python 类型、提取文档 JSON/Python 片段做检查，并建立语义负例、Adapter 一致性与兼容性回归。不能把 Schema 校验通过当成权限/时间正确。风险是只测镜像实现的单元测试；用独立的协议夹具、契约测试和真实端到端抓包补足。见 [12](12_VALIDATION_AND_OPEN_QUESTIONS.md)，ADR-0004/0008。

## Q11 固定步长、异步消息、程序执行的时间语义？

以整数 tick 表示 sample/estimate/目标生成时刻，以日志字段记录 delivery/ingress；激活时冻结输入，输出只能在 Host 预定的 `output_commit_tick` 提交。玩家只发布目标，不逐条指定未来生效/终止时间。早到不提前、迟到不补写过去，reset 更换 run。受控测试可有界等待，实时比赛记录实际超时。代价是可见延迟；同构建物理重放不等于跨硬件重跑 Python 位级一致。见 [03](03_PROTOCOL_SPECIFICATION.md)、[07](07_SIMULATION_DESIGN.md)，ADR-0010/0011/0014。

## Q12 Arena 怎样防未经授权信息/资源并保持公平？

服务器运行锁定 artifact，每机器人强化沙箱与配额，禁止外网和跨 worker 通信；同版本/profile/硬件类别，服务器计算分数，隐藏种子，多出生位交换，超载整场处理。风险是内核漏洞、共享硬件侧信道与预算抖动；需攻击测试、补丁、审计和重赛机制。不能把普通子进程当服务器安全边界。见 [08](08_RUNTIME_AND_SECURITY.md)，ADR-0006/0013。

## Q13 服务端和客户端分别维护哪些状态？

服务端权威维护真实世界、规则/命中、时钟、传感器、许可、部署生效、资源执行和评分。客户端维护草稿、布局、手动相机、授权缓存、显示插值与编辑撤销；玩家算法维护独立估计。客户端意图须过服务器验证。风险是把 UI 预测当结果；明确预测标签，任何成绩/碰撞都回到 Authority。见 [02](02_SYSTEM_ARCHITECTURE.md)、[04](04_STATE_AND_VIEW_MODEL.md)，ADR-0001/0006。

## Q14 版本升级怎样保留已有项目？

区分协议、SDK、Manifest、模板和内容版本；迁移先备份/计划/预览，任何已有文件不自动覆盖，显式合并产生新 revision。部署 artifact 不可变，旧 SDK 在声明支持窗口内保留；不支持时可导出与编辑。风险是云同步/大小写冲突和依赖不可复用；用 CAS、内容摘要、精确依赖与跨平台导入测试控制。见 [06](06_WORKSPACE_AND_TEMPLATES.md)，ADR-0009/0012。

## Q15 错帧、过期时间与非法协方差如何处理？

按层校验：Schema 检查形状，数值检查有限/范围/对称/PSD，Frame Registry 检查授权且无环变换链，Scheduler 检查 run/未来/过期与提交窗口。非法输出拒绝整模块子批次并反馈脱敏错误；合法漂移保留，旧显示自然过期。风险是宽松容差掩盖 bug 或错误把未知 covariance 当零；使用明确参考尺度和负例覆盖。见 [03](03_PROTOCOL_SPECIFICATION.md)、[04](04_STATE_AND_VIEW_MODEL.md)，ADR-0004/0007。
