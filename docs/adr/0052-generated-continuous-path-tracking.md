# ADR-0052 自动路径参考与真实轨迹裁判

- Status: Accepted
- Date: 2026-11-05
- Scope: Navigation C4；既有物理、传感器、20ms及6tick合同不变

## Context

用户确认连续追踪公开路径，使用现有仓储地图和零初态，裁判自动生成12–18m安全路线；玩家只新增追踪算法。现有C3逐航点到达组件没有完整折线评分、顺序检查点与碰撞失败，不能偷偷沿用其目标切换或开放真实位置。

## Decision

在可信场景准备阶段生成并冻结路径，复用地图解析和ResolvedScene缓存。采用有界网格搜索、可见性简化、圆角、重采样与最终通道/长度/形状复验；外接圆加余量覆盖完整车体。独立路径随机流不消耗传感器流；部署/测试不重生成。全部生成参数在独立课程YAML。

完整路径按显式task_inputs授权一次提供，只读NumPy (N,2)传给PathFollower.update，输入位姿仍是玩家EKF。Twist只作为轮控制参考，Authority独立拒绝主动倒车并执行限幅。沿用固定输入冻结、提交和失败/看门狗。

独立可复用PathTracking裁判按真实质心到完整折线的逐tick距离做时间加权RMSE/最大偏离，自动检查点只验证顺序。真实接触在子步锁存，仅私有裁判可读。终点停稳即结算，碰撞/控制故障/偏离优先成功，成功优先超时。UI距终点标量与终局误差单独显式授权，不加入机器人输入。

## Alternatives

固定路线/控制点违反自动生成；同批串联改变时延；沿离散点评分引入采样误差；逐点停车改变课程目标；以玩家位姿评分可伪造成功。朝向搜索与完整规划框架成本过大，本轮采用可复验的保守圆通道。控制器不能复用旧传感器记录冒充新闭环，实际评价必须重建场景。

## Consequences

需要同步配置Schema、启动参考/SDK只读数组、任务事实、模板升级、独立图层、教材和测试；旧源码及接口保留。保守通道可能拒绝窄路，失败必须有界报错。当前细节见 [40](../40_NAVIGATION_CONTINUOUS_PATH_TRACKING.md)。原生受控seed0/1/2/7、Pyodide实际页面seed0/7、时序/权限/迁移与真实编辑部署通关均有证据，范围为本机Linux/Firefox；完整回归及失败记录见 [验收](../reports/NAVIGATION_PATH_TRACKING_VALIDATION.md)。不宣称硬实时或其他平台支持。
