# ADR-0029 关卡运行时限、主动结束与玩家生命

- Status: Accepted
- Date: 2026-10-25
- Scope: C0–C2；局部扩展 ADR-0022 的尝试生命周期

## Context

用户要求关卡不能无限运行、写代码时间不计入首次运行预算，并能主动终止错误程序；C2 起玩家需要与敌车相同 HP，死亡判失败。

## Decision

采用用户确认的 60/60/120 仿真秒。C0 首次有效人工输入起算，C1/C2 首次成功玩家部署起算；测试不计时。开始后持续计时，重复部署与回滚不重置。准备期禁止 C1/C2 人工执行器操作，显式执行工作区代码属于启动部署。任务页与编辑器共享 Authority 的主动结束 API。

2026-10-26 按用户要求收紧 UI 工作流：适用于所有 Campaign 关卡的 running 阶段，禁止再次进入代码编辑器；结束或重置后恢复。关闭编辑器始终把键盘焦点交回游戏画布，防止 Space 触发编辑按钮。所有编辑入口共用阶段门，不按关卡 ID 区分；主界面日志和结束按钮保持可用。此前允许边运行边打开编辑器的 UI 行为被替代；Authority 的计时和底层热部署语义保留。接受依据为用户明确要求，检查见 [阶段锁定验收](../reports/EDITOR_ATTEMPT_LOCK_VALIDATION.md)。

玩家生命模型由本关敌车配置派生，Core 在子步末移除致死玩家的刚体和碰撞体。Authority 在 tick 末按玩家死亡、时限内目标完成、超时顺序结算；同 tick 双方死亡判失败，最后一个预算 tick 存活击杀可通关。失败报告固定，不奖励关卡解锁；真实世界和剩余弹丸沿用原结束规则继续。

## Alternatives

墙钟会把设备性能与算法可用步数混在一起；加载页面即计时会消耗编辑时间。每次部署重置可无限延长尝试。前端自行扣血/计时无法保持权威；只隐藏死亡车体会留下碰撞幽灵。

## Consequences

新增公开管理状态字段和 reason，保持机器人协议和原 status 兼容。当前敌车仍不主动射击，玩家可被反弹自伤。需要明确 CLI 启动代码与 UI 系统脚手架的区别；浏览器后台节流限制依然存在。规则、接口与证据见 [25](../25_ATTEMPT_RULES_AND_CONFIGURATION.md)。
