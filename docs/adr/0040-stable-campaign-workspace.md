# ADR-0040 Campaign 工作区身份独立于运行配置

- Status: Accepted
- Date: 2026-10-27
- Scope: 默认教学项目的目录选择与旧工作区恢复；不修改算法、关卡或协议

## Context

用户报告接口升级后 C1/C2 已写代码在 F2 中消失。检查发现源码仍在早期从 C0 启动的版本库，而直接从 C1/C2 启动打开另一个只含模板的版本库。原 key 取 seed、Module 入口和 control_sources；同一服务内切关复用原库，但重启时会因关卡控制权不同而选另一库。原测试只覆盖同控制模式的 C1→C2 或显式共享目录，未覆盖 C0→C1 和直接启动。

## Decision

默认 Campaign 项目使用 seed 与固定 campaign scope 生成身份，不包含关卡 ID、控制源、模板版本、Module 入口或物理配置。C0–C5 及后续课程因此共享一个长期项目。不同显式 seed 保持独立；沙盒沿用已有身份，--workspace-store 保持最高优先级。

新默认目录尚不存在时，按已有课程 profile 计算旧 key 并检查已有库。将当前 Python 文件与课程模板及其 ledger 中的历史生成版本比较，识别包含非模板实现的项目；唯一候选优先于模板空库。完整复制该项目、全部历史与 archive，校验后原子发布，旧目录保留。存在多份不同已编辑项目时明确拒绝自动选择，提供 --workspace-store 路径，不按修改时间猜测、不合并同名算法。目标已存在时继续使用它，不反复迁移。

损坏 HEAD、历史摘要或不安全链接不得触发新模板替代；原子复制失败可重试。选择与发布沿用父级迁移锁及源库文件锁。当前教学进度仍单独保存，不从代码文件推断通关。

## Alternatives

只给用户一条旧目录启动命令能临时找回代码，但默认启动仍会分叉。按最近修改时间选库会优先选中新建空模板；直接合并同名算法无法安全决定所有权。自动重写旧 key 还会失去历史和回滚点，均不采用。

## Consequences

默认项目可跨控制权和课程接口升级稳定重开；旧目录占用额外空间，作为可恢复备份保留。多个真实旧项目不能无歧义自动处理，需明确选库。正在运行的旧服务需重启才能加载新选择逻辑；迁移后不继续使用旧实例写源库。

## Validation

tests/test_workspace_storage.py 覆盖 C0–C5 分别启动、旧 C0 实现优先于新模板、所有 revision/archive 字节不变、多候选冲突、并发、发布失败和缺 HEAD。实际恢复与完整回归见 [验收](../reports/WORKSPACE_IDENTITY_VALIDATION.md)。
