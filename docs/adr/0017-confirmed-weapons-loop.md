# ADR-0017 用户确认的 M1b 武器闭环与授权接口

- Status: Accepted
- Date: 2026-10-22
- Scope: 炮台、弹丸、冲量、开火业务幂等与练习视图
- Amends: ADR-0015 的“武器仅建模”阶段限制、13 的后坐作用刚体；03 的通用短请求缓存对开火采用业务特例

## Context

用户明确先实现 M1b，要求武器/弹丸未约定处逐项询问，并要求同时提供机器人炮台与开火接口。普通速度流与离散单发语义不同；UI 显示弹丸会泄漏隐藏位置。原后坐作用炮台的约定已被用户改为作用底盘且按底盘能力投影。

## Decision

实现 [14 的 W01–W17](../14_WEAPONS_DESIGN.md) 用户确认模型：独立质量炮台、中心转动关节、相对角速度力矩伺服、反作用；发射前炮口速度继承、单发/冷却；弹丸连续扫掠与互毁图、稳定同时顺序、半开寿命、离膛后自伤、静态靶标。受击为弹丸世界动量；后坐仍为相对发射动量。两者作用于底盘，差速保留车体 x，全向保留完整方向，保留实际作用点力臂，不增加车体质量。

受击在固定子步末施加，不回滚当前子步；按碰撞时朝向投影并保留当时世界力臂。接受最大 1/240 s 的冲量门延迟。炮台无环境碰撞外形，车体/靶标采用既有静态接触参数。所有参数在唯一配置。

新增 turret_velocity@1 Topic、fire_command@1 Command、weapon_state@1；通过 SDK 类型与 ctx.fire、固定提交门、受信控制源选择。开火业务日志按 run/绑定主体/ID 保存整个 run，不淘汰；达到配置容量拒绝新 ID，不悄悄失去幂等保证。人工/程序不会同时获得同一执行器写权，运行中切换留待后续。

默认估计视图不发真实弹丸；显式练习策略使用 System Pose Provider → Selector → Gateway，并新增严格 view_snapshot@2 实体结构。Python 输入保持不含真值。旧 @1 的空 objects/effects 约束不变。配置内部版本升级为 1.1，协议主版本仍是未发布草案 1.0。

## Alternatives

贴图炮台不能反映双刚体惯性；纯离散位置检测会漏高速互撞；在 Runtime 内处理碰撞会绕过物理权威。所有模式都给 UI 真值再隐藏违反 ADR-0007。仅保留短请求缓存会使旧开火重试再发一弹；不受限的永久日志则造成内存无界增长。采用有界日志满后拒绝，优先明确副作用语义。

## Consequences

受击后当前子步的后续接触仍基于既定插值路径；分离容差与固定质量/差速横向动量投影均为公开近似，不宣称完全守恒。代码新增可测试的 cannon/turret 子系统，但不引入通用机器人中间件或 ROS2/DDS。

练习视图一旦获授权就不能“撤回玩家记忆”；只能启动时明确选择。普通 CPython worker 仍只允许运行本人可信代码。多坦克、生命值、自动连射、动态租约和服务端隔离不在此决策实施范围。

## Evidence / Acceptance Criteria

接受依据是用户逐项明确答复，并由 [武器测试](../../tests/test_weapons.py)、Core 内部事件/冲量测试及 [M1b 报告](../reports/M1B_VALIDATION.md) 验证。语言、完整前端与安全运行时技术 ADR-0002/0003/0013 保持 Proposed；本机原生和无头 WASM 探针不是全平台或安全沙箱证明。
