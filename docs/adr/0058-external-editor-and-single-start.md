# ADR-0058 VS Code 外部编辑与单次 Start

- Status: Accepted
- Date: 2026-11-18
- Amends: 0009的编辑副本、0012的玩家操作流程、0056/0057的Godot内置编辑器部分

## Context

用户要求删除内置代码编辑器，用VS Code打开玩家代码。现有工程以不可变JSON快照存储，直接打开快照无法正常多文件编辑，也不能让编辑器改写历史。用户已确认：在userdata建立真实编辑目录，保存不改变运行版本；允许运行期间编辑。随后明确要求保存后只点Start，无需手动测试/部署。

## Decision

每个原版本库增加 `files/` 编辑副本和 `EDITABLE.json` 基线，不更换原工程身份、revision、ledger或存档。F2/按钮由受控本机API调用已安装VS Code，打开当前课程目录和教材声明的主要文件。命令与扫描限额取desktop.yaml，不接受请求指定的程序、目录或CLI选项，不使用shell，不安装扩展，也不关闭玩家的编辑器。

保存只落盘；Start读取稳定、有界、经过路径校验的文件，以原文件锁/CAS生成不可变版本，并自动编排现有独立检查和正式启动。内部仍执行语法、依赖、Contract、权限、单元/短输入和适用的一次性规划检查。失败保留Python日志，不能激活不合法版本。测试与正式Worker仍独立，固定提交门和30ms实验性原生profile不变。被动人工课程由已有processing配置决定，无需算法启动；不按关卡ID分支。

Godot删除CodeEdit、源码文件树、保存、测试和部署按钮；保留Start、停止、只读任务说明、升级预览及日志。运行期间可编辑，当前快照不可变；新版本须停止后Start。选择课程载入准备场景，Start显式建立新的尝试；不通过热部署重置旧尝试计时。

外部文件与版本库采用逐文件三方比较。双方修改同一路径且内容不同时拒绝并列出路径；不猜测合并。框架升级先捕获已保存修改，再预览/显式应用；同步前再次检查基线。更新旧磁盘文件时先移入editable-recovery，独占创建新文件，不覆盖竞争中的另一次保存。中断可重入，旧源码及历史保留。未保存的VS Code缓冲不在游戏控制范围内。

## Alternatives

直接编辑revision JSON会破坏不可变历史；每次Ctrl+S生成版本需要文件监视和更复杂的事务边界；启动可变文件会使部署不可复现，均不采用。保留内置编辑器作回退违背用户要求。跳过检查或放宽周期预算不是简化操作所必需，亦不采用。

## Consequences / Validation

VS Code成为外部编辑依赖；未安装/不在PATH时报告原因和真实目录，用户可配置可执行路径。SDK路径与Python解释器建议仅在缺失的.vscode/settings.json中创建，不覆盖已有配置。文件保存和Start之间可能有修改，界面明确当前运行revision；游戏不保存编辑器未落盘缓冲。

版本库完整导出包含已经捕获的源码；尚未Start的磁盘草稿、编辑器设置和并发保存恢复副本须随整个userdata备份，不能宣称旧快照备份覆盖了它们。本机可信代码和强沙箱未实现的边界保持。

规范与验收见 [45](../45_EXTERNAL_EDITOR_AND_START.md)、[本轮报告](../reports/EXTERNAL_EDITOR_AND_START_VALIDATION.md)。Accepted针对用户确认的工作流与源码保护合同，不代表全部平台/编辑器版本或十三关GUI流程均已验证。
