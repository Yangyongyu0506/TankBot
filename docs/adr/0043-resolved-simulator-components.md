# ADR-0043 完整底盘、传感器实例与已解析场景

- Status: Accepted
- Date: 2026-10-29

## Context

底盘动力学仍分布在 game.yaml；敌车复用玩家伺服/限制；传感器的配置、随机流与调用分散；关卡重试重复拼装可变字典。用户明确要求完整模型资产、统一实例接口和可复用的已解析定义。

## Decision

底盘 profile 2.0 包含质量/惯量、轮组、受限伺服、阻力、控制器限制与外观；世界时钟、求解器、接触世界及武器继续独立。生成现有私有 DTO，不改玩家接口；敌车按自身模型生成伺服与限制。

传感器定义显式声明 id、robot_id、mount、period_ticks、random_stream 和 output，通过统一调度器执行 create/reset/sample/close，Rust 样本适配器与 Python 观测适配器共享时间入口。保留现有采样周期、安装限制和噪声序列；不借重构引入新的测量模型。

ResolvedScene 在创建世界前完成资源、机器人及传感器引用和结构语义校验，保存不可变定义。SceneResolver 缓存选定场景，重试共享定义但新建世界、随机状态、消息缓存、Worker 与 run_id。可变字典只作为旧宿主/私有 Core 的每实例适配输出，不作为缓存真相。

## Alternatives

仅移动 YAML 不解决敌车参数串用；只包装字典不能保证定义不被运行状态污染；统一搬进 Rust 会扩大重构并改变平台成本。采用已确认后端的薄实例适配器，不新增通用中间件或 YAML 脚本。

## Consequences

模型和实例版本需要同步 Schema、工具与测试。旧内联/几何配置有显式兼容适配；正式资产不重复保存参数。非零安装、任意多机器人、不同窗口 IMU 等新物理仍需要独立确认；当前未知配置必须拒绝。

## Validation

接受条件：同输入下六关/两底盘物理和观测序列基线一致；模型参数独立生效；实例错误和重复输出拒绝；同定义重建无状态串用；原生/WASM、模板与进度回归通过。接受证据见 [验收报告](../reports/SIMULATOR_REFACTOR_VALIDATION.md)。
